# LW Vision 功能缺口与工具缺失排查报告

> 排查日期：2026-08-31 ｜ 方法：只读代码盘点 + 对照 CKVisionBuilder 手册工具清单 + 竞品调研（OpenIVS / DLCV.AI / 军哥MIP / 视觉芯）
> 范围：`plugins/tools/*`、`src/engine`、`src/hal`、`src/ui`、`src/app`
> 结论先行：**LW Vision 已完成"能跑的壳 + 40+ 工具 + AI 推理 + Modbus 全链路"的工程地基，但距离"成熟商用视觉软件"还有三大结构性缺口：(1) 数据流（位置补正→ROI 跟随）只写了数据、没有任何工具消费；(2) 标定只有标量比例，无畸变/手眼/多点仿射；(3) 若干"看起来有"的工具是占位实现（OCR 数轮廓、图像补正实为光照校正）。**

## 三、重点评估：三大核心能力现状

### 3.1 数据流打通（找圆→位置补正→ROI 跟随）—— ❌ 未实现，最关键缺口

**结论：目前"节点连线是画出来的，不传数据"。**

- 现状（代码实证）：
  - `PositionCorrection::execute()` 计算 `correctedX/Y/Angle`，并向 context 写入 `coord_cos/coord_sin/coord_originX`（位置补正/坐标系统/结束补正 均只**写**）；
  - 全仓库 grep `coord_cos|coord_originX|coord_sin|correctedX`：**只有 4 个文件在写，0 个检测/几何工具在读取**——没有任何工具把自己的 ROI/测量坐标按补正矩阵变换；
  - `FlowEngine::doExecute()` 按工具列表**线性顺序**遍历执行，`FlowEditor` 中的 `ConnectionItem` 仅作可视化，`connectionCreated` 信号没有接到执行引擎；
  - 路线图自己也承认"目前节点连线并不真正传数据"（完美化路线图 阶段2 待办）。
- 后果：工件偏移/旋转后，后续工具的 ROI 不会跟着动——这是 CKVision 流程的"灵魂"（形状匹配→位置补正→检测组全部在补正坐标系内），缺了它整套"通用定位+检测"场景都做不扎实。
- 建议实现（无新依赖）：
  1. 引擎层加一个 **CoordinateFrame 服务**（存 cos/sin/originX/Y，提供 `worldToImage/point/ROI` 变换），`PositionCorrection` 写入、`EndCorrection` 清空（成对语义已有）；
  2. 各 Detection/Geometry 工具的 `execute()` 开头统一调用"当前帧 + 补正矩阵"把定义在模板坐标系的 ROI 中心/角度变换到图像坐标再执行；
  3. FlowEditor 连线 → 当工具间存在可推断的引用关系时，连线高亮/自动填充 `$(工具名.键)`（可先用"同流程前向引用"简化，不做严格 DAG 数据流）。

### 3.2 多相机 / 多流程 —— ⚠️ 接口有、闭环无

- `HardwareManager` 支持 1~8 相机数组、`MultiViewWidget` 支持 1~16 分屏——**多相机 UI/接口骨架在**。
- 但只有 1 个真实相机插件（度申）+ 虚拟相机；无"每相机独立工作线程 + 独立流程绑定"的运行时模型（`FlowEngine` 是单引擎串行执行多 Flow，未按相机并行）；无多相机硬件同步触发、无相机间时序。
- 竞品：CKVision 多相机各挂独立流程并支持并行流程；海康 VisionMaster 多相机并行流是标配；OpenIVS 的 Sequence 图本身就是"设备级并行编排"。
- 建议：阶段5 按"每相机 1 个工作线程 + 1 条流程 + 独立 ToolContext"落地；多相机同步先做"软触发 + 帧计数对齐"，硬件触发留接口。

### 3.3 标定 —— ❌ 只有"标量比例"

- `Calibration` 工具 3 个"方法"（两点/已知比例/棋盘格）**全部走同一个 `ratio = realLen/pixelLen` 公式**，所谓"棋盘格标定"只是改了个名字，没有棋盘格角点检测、没有内参/畸变系数；
- 无相机畸变标定（OpenCV `calib` 模块已捆绑进本项目，却没用上）；
- 无手眼标定（相机-机器人坐标关系）；
- 无多点仿射/透视坐标校准（CKVision 坐标校准1/2）；
- `ImageCorrection` 名字误导：是亮度/对比度/白平衡，不是几何校正。
- 建议：用已捆绑的 `opencv2/calib` 做"棋盘格标定 → 内参+畸变系数 → 去畸变工具"；`calibrateHandEye` 做手眼标定（OpenCV 已有 API）；坐标校准用 `estimateAffine2D` 多点拟合。

## 五、结论与建议

1. **第一优先级不是加工具，是把 P0-1（数据流打通）做对**——这是"从演示壳到工业软件"的分水岭，路线图阶段2 已明确列出，应最先投入。
2. **标定要"动真格"**：畸变标定 + 多点坐标校准 + 手眼标定三位一体，OpenCV calib 模块已捆绑、成本低、客户感知强。
3. **占位工具要"转正"**：OCR（数轮廓）、图像补正（光照校正）、标定校准（假棋盘格）三处名不符实，会直接损伤客户信任。
4. **客户高频刚需**：声音报警、数据报表趋势图、检测间距/像素统计、存储图像、几何组合测量——都是小成本高感知项，建议随 P0 一起快速补齐。
5. 3D 测量与细分专用工具（焊缝/涂胶/字符验证）**明确不做**，聚焦通用平台 + 螺纹/AI 两个拳头。
