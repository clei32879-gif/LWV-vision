# LW Vision 代码质量与可靠性排查报告

> 排查日期：2026-08-31 ｜ 排查人：AI 助手（资深 C++/Qt 工业软件代码审查，静态排查）
> 范围：`src/engine`、`src/hal`、`src/ai`、`src/core`、`src/utils`、`src/app`、`src/ui`、`plugins/`（40+ 工具插件，全工程只读，未修改任何源代码）
> 方法：通读关键源码，重点核查 ①线程安全 ②错误处理 ③内存/资源生命周期 ④崩溃点 ⑤未完成代码 ⑥日志与可维护性；每条含 `文件:行号 | 问题 | 建议修复`，按 **高 / 中 / 低** 三级分级。

## 一、结论摘要

LW Vision 架构方向正确（FlowEngine 多线程快照执行、last* 结果带互斥锁快照、Modbus 主从站自研、工具注册表单例），但从**可靠性**角度，当前处于"**能演示、不能稳定长时间运行**"的阶段。最突出的系统性问题有四类：

1. **线程生命周期错配**：QtConcurrent 工作线程执行流程时，`Flow`/工具/`FlowEngine` 对象可在 UI 线程被删除（新建/加载项目、关窗），且停止流程与释放资源（Modbus 连接池）之间无同步——这是本项目**最可能的运行时崩溃来源**（use-after-free）。
2. **工具对象生命周期缺陷**：`Flow::m_tools` 明确"非拥有"，但全工程**没有任何一处 delete 工具**，每次新建/加载项目泄漏整条流程的全部工具对象。
3. **共享无锁状态**：工具 `m_properties`/`m_resultData`/`m_status` 在工作线程写入、UI 线程读取（属性对话框、结果键枚举），无锁，存在数据竞争。
4. **"信号断链"死功能**：流程编辑器右键菜单的删除/上移/下移/启停/复制/粘贴、连线、双击编辑等信号只 emit 无 connect（与已完成的《UI与交互体验排查》结论一致，本报告从可靠性角度确认并给出修复级建议）。

总体：**高 22 / 中 48 / 低 40**（engine/hal/ai/core/comm/app + 子代理A(ui) + 子代理B(plugins/tools) 已全部合并；含 3 个子代理逐文件通读与本人复核）。

## 二、最重要的 10 条（按修复优先级）

1. **[高] 工具对象从不删除 → 每次新建/加载项目泄漏整条流程工具；运行中销毁 Flow 还会使工作线程持悬垂工具指针**（`src/engine/FlowEngine.h:80`、`src/core/ProjectManager.cpp:45-49/79-84`）。
2. **[高] 关窗/加载项目时未停止流程线程即释放资源（Modbus 连接池 releaseAll、关相机）→ 工作线程 use-after-free**（`src/app/MainWindow.cpp:866-871`、`src/hal/ModbusTcpMaster.cpp:26-33`）。
3. **[高] executeOnceAsync/startRunning 的 QtConcurrent 任务捕获裸 `this`/`flow`，不可取消、不可等待；runLoop 与 executeOnceAsync 可并发 doExecute 同一 Flow → 工具结果/属性数据竞争**（`src/engine/FlowEngine.cpp:361-372/399-404`）。
4. **[高] PropertyResolveGuard 在工作线程改写工具属性，与 UI 线程属性编辑数据竞争**（`src/engine/FlowEngine.cpp:55-75`）。
5. **[高] MainWindow onEditToolProperties 枚举 `tool->resultData().keys()`（UI 线程），工作线程正在写 → 数据竞争**（`src/app/MainWindow.cpp:474`）。
6. **[高] Flow 所有权不一致：MainWindow 用 `new Flow(this)`，ProjectManager 用 `new Flow(m_engine)` → 关窗双重释放/悬垂风险**（`src/app/MainWindow.cpp:394` vs `src/core/ProjectManager.cpp`）。
7. **[高] 用户密码明文存储 + 默认 Admin 空密码 → 权限体系形同虚设**（`src/core/UserManager.cpp:37-41`、`UserManager.h:40`）。
8. **[高] AIDetection 读取未定义属性 `detectionIsNG` → 缺陷检测"检出即NG"判定永远不生效，NG 品全部漏判**（`plugins/tools/AIDetection/AIDetection.cpp:137` vs `47-55`）。
9. **[中/高] Modbus IO 驱动 TCP 分支未探测连通即报"已连接"；吹气/脉冲用 msleep 阻塞工作线程**（`src/hal/ModbusIoDriver.cpp:54-77/148-153`）。

## 三、高优先级（可能导致崩溃 / 数据错误 / 安全问题）

### 3.1 线程生命周期与并发（engine / app）

**[高] H-1 工具对象内存泄漏 + 运行期悬垂**
- 位置：`src/engine/FlowEngine.h:80`（`m_tools` "非拥有, 外部管理生命周期"）、`src/core/ProjectManager.cpp:45-49/79-84`（`newProject/loadProject` 只 `setParent(nullptr)+deleteLater(flow)`，从不删工具）
- 问题：`MainWindow::onToolAdded` 用 `ToolRegistry::createTool`（`new`，无父对象）后仅 `flow->addTool`；`Flow` 析构/clear 都不 delete 工具。每次新建/加载项目，旧流程全部 `ITool` 泄漏。更危险的是：若在运行期删除 Flow（loadProject 重建），已 `deleteLater` 的 Flow 内工具指针被工作线程（`snapshotTools()` 已取副本但工具对象本身存活于 Flow 生命周期内……工具并不随 Flow 删除）——实际是工具**不随 Flow 删除**，所以工作线程持有的 `ITool*` 在项目重建后变成"仍存在但被新流程复用前的旧对象"，若工具无归属则不会立刻崩溃；但若未来补上删除逻辑而不同步停止线程，将直接 use-after-free。
- 建议：①明确所有权：`Flow` 拥有工具并在析构/clear 时 `delete`，同时保证删除前 `FlowEngine::stopRunning` + 等待工作线程结束（引入"正在执行"引用计数或 `QFuture::waitForFinished`）；②`ProjectManager` 重建流程前先停引擎。

**[高] H-2 关窗未停线程即释放资源 → use-after-free**
- 位置：`src/app/MainWindow.cpp:866-871`（closeEvent：`closeCamera()` + `ModbusTcpMaster::releaseAll()` + `saveSettings()` 后直接 accept）
- 问题：连续运行/单次执行的工作线程可能正通过 `ToolContext` 持有 `m_camera`/Modbus master 指针；`closeCamera()` 与 `releaseAll()`（对池内 master 执行 `deleteLater`）与线程内 `transact()`/`grabFrame()` 无任何同步 → 关窗瞬间崩溃或未定义行为。
- 建议：closeEvent 中先 `m_flowEngine->stopRunning(true)` + 记录并等待工作线程结束（`QFutureWatcher`/引用计数），再释放硬件与连接池；必要时拒绝关闭并提示"仍在执行"。

**[高] H-3 QtConcurrent 任务不可取消/不可等待，捕获裸指针**
- 位置：`src/engine/FlowEngine.cpp:361-372`（`(void)QtConcurrent::run([this, flow]{ doExecute(flow, context); m_executing=false; })`）、`385-397`（`startRunning` 同）
- 问题：①返回的 `QFuture` 被丢弃，无法等待/取消；②lambda 捕获 `this`（FlowEngine）与 `flow` 裸指针，若引擎或流程在任务运行中被销毁（H-1/H-2 场景）→ 悬垂调用；③`m_executing` 用 `compare_exchange` 保护单次执行，但**连续运行 `runLoop` 的 `m_executing=true` 是普通赋值**，与 `executeOnceAsync` 的 CAS 不同步：executeOnceAsync 执行中用户点"运行程序"→ startRunning CAS `m_running` 成功 → runLoop 与 executeOnceAsync **两个线程并发 doExecute 同一 Flow** → 工具 `m_resultData`/`m_properties`/`m_status` 数据竞争。
- 建议：①保存 `QFuture` 并暴露 `waitForFinished`/取消；②统一用"引擎级执行互斥"（单 `std::atomic_flag` 同时约束单次与连续运行，或 `QMutex`），杜绝两条执行路径并发；③用 `QPointer<Flow>`/弱引用或在工作线程结束时校验引擎存活。

**[高] H-4 PropertyResolveGuard 工作线程写属性与 UI 编辑竞态**
- 位置：`src/engine/FlowEngine.cpp:55-75`（PropertyResolveGuard 构造/析构调用 `tool->setProperty()` 替换/恢复 `$(...)` 引用）
- 问题：属性解析在工作线程改写工具 `m_properties`（`QVariantMap`，无锁）；若同一时刻用户在属性对话框保存该工具属性 → 数据竞争（Qt 容器非线程安全）。
- 建议：执行期间对工具属性读写加 `QMutex`，或 PropertyResolveGuard 改为在 `ToolContext` 副本上解析（不写回工具对象），执行完再原子提交。

**[高] H-5 onEditToolProperties 读 resultData 与工作线程写竞态**
- 位置：`src/app/MainWindow.cpp:461-485`（`t->resultData().keys()` 用于构造"可链接数据"下拉）
- 问题：工作线程执行 `setResultData`（写 `m_resultData`）与 UI 线程枚举 keys 无锁 → 数据竞争（可能崩溃/读到半写状态）。
- 建议：`ITool::resultData()` 改为带锁返回副本，或仅用"属性定义出的结果键"（静态）作为可链接项，不读运行时结果。

**[高] H-6 Flow 所有权不一致**
- 位置：`src/app/MainWindow.cpp:390-397`（无流程时 `new Flow(this)`，父=MainWindow）vs `src/core/ProjectManager.cpp`（`new Flow(m_engine)`，父=引擎）
- 问题：同一对象两种父归属。MainWindow 析构会删除子 Flow，而 `FlowEngine::m_flows` 仍持有其指针；ProjectManager 删除 Flow 时又对部分 Flow 无感知 → 悬垂/双重释放风险；且 ProjectManager `deleteLater` 只针对它自己创建的 Flow，MainWindow 自建 Flow 在新建项目时不会被清理（同时 m_flows 残留悬垂）。
- 建议：统一由 `FlowEngine` 或 `ProjectManager` 管理 Flow 所有权，禁止以窗口为 Flow 的 parent；`MainWindow` 只通过引擎创建/注册。

### 3.2 数据/判定正确性（engine / plugins / core）

**[高] H-7 用户密码明文 + 默认 Admin 空密码**
- 位置：`src/core/UserManager.cpp:37-41`（明文 QString 数组 + `==` 比较）、`UserManager.h:40`（默认 Admin）、`UserManager.cpp`（空密码直接登录）
- 问题：任何可读 `config/users.json` 的人可拿到管理员密码；默认空密码=出厂即管理员。权限体系形同虚设。
- 建议：密码改 `QCryptographicHash::Sha256 + 随机盐` 存储；默认角色 Operator；首次使用强制设密码，空密码禁止登录 Admin。

**[高] H-8 AIDetection 未定义属性 detectionIsNG → NG 漏判**
- 位置：`plugins/tools/AIDetection/AIDetection.cpp:137`（`propertyValue("detectionIsNG").toBool()`）vs `47-55`（propertyDefs 只有 modelPath/confThreshold/iouThreshold/goodClasses/minScore）
- 问题：`detectionIsNG` 未在属性定义中声明，`propertyValue` 恒返回默认 `false` → 缺陷检测场景（检出即NG）永远按"检出即OK"判定，NG 品全部放行。这是**生产安全级缺陷**。
- 建议：在 propertyDefs 增加 `boolProp("detectionIsNG", ...)`（并给 UI 默认值），或改用已有 `goodClasses` 语义统一判定。

**[高] H-9 ModbusComm INT32 有符号左移未定义行为**
- 位置：`plugins/comm/ModbusComm.cpp:181-183`（`(static_cast<qint32>(values[i*2]) << 16)`）
- 问题：高 16 位 ≥0x8000 时有符号左移越界（UB），且高位符号扩展导致读值错误。
- 建议：用 `quint32` 组合后 `memcpy` 到 `qint32`；INT32/FLOAT 读取 count*2 超 125 上限时按帧分段。

**[高] H-10 SerialPort 裸指针泄漏 + 悬垂**
- 位置：`plugins/comm/SerialPort.cpp:27-28/80-87`（`context.getData("__SerialPort").value<void*>()` 无类型校验存取）
- 问题：串口对象以裸 `void*` 存 context，close 只 `close()` 不 `delete` → 反复开关泄漏；类型强转无校验，类型不符时悬垂/崩溃。
- 建议：用 `QPointer<QSerialPort>` 或 `shared_ptr` 持有并随 context 释放；`static_cast` 前校验类型。

### 3.3 Modbus 连接池 / IO（hal）

**[高] H-11 连接池 releaseAll 与工作线程无同步 → use-after-free**
- 位置：`src/hal/ModbusTcpMaster.cpp:26-33`（`releaseAll`: 遍历 `deleteLater` + `s_pool.clear()`）、`src/hal/ModbusRtuMaster.cpp`（同构）
- 问题：池是静态全局 `QMap<QString, ModbusTcpMaster*>`，`acquire` 返回裸指针，无引用计数；工作线程可能在 `transact()`（持 `m_mutex`）期间，UI 线程 `releaseAll` 执行 `deleteLater` 并清空池 → 随后事件循环处理 `deleteLater` 释放对象，工作线程访问已释放 master → use-after-free。且 `releaseAll` 不取各 master 的 `m_mutex`，与 `transact` 完全无同步。
- 建议：①`releaseAll` 前先确保所有执行线程已停止（与 H-2 一并处理）；②池改 `std::shared_ptr` 管理，acquire 持强引用，天然防释放；③或 `releaseAll` 只断开不 delete，进程退出时统一清理。

**[中/高] H-12 Modbus IO 驱动 TCP 分支未探测连通即报已连接**
- 位置：`src/hal/ModbusIoDriver.cpp:54-77`
- 问题：TCP 分支 `acquire` 后直接 `m_connected=true`，未像 RTU 分支/PLC 驱动那样做 `ensureConnected` 探测 → PLC/IO 不可达时 `isConnected()` 仍返回 true，后续读写才失败，误导流程判定。
- 建议：TCP 分支 connect 时也做一次 `readRegisters` 探测（参考 `ModbusPLCDriver::connect`），失败置 `m_connected=false`。

**[中/高] H-13 吹气/脉冲/延时阻塞工作线程**
- 位置：`src/hal/ModbusIoDriver.cpp:148-153`（pulseOutput 用 `QThread::msleep`）、`src/hal/ModbusPLCDriver.cpp:159-183`（blowOK/blowNG 同）、`plugins/logic/Delay.cpp:20-23`（忙等+processEvents）
- 问题：同步阻塞会卡住整个流程工作线程（脉冲 500ms 则整条流程停 500ms），`Delay` 用 `while+msleep(10)+processEvents` 在非 GUI 线程无意义且可能重入。
- 建议：脉冲用异步定时器/专用 IO 线程；Delay 直接用 `QThread::msleep(delayMs)` 一次性休眠或异步 QTimer。

### 3.4 src/ui 模块（子代理A交叉确认，高）

**[高] H-14 ToolStatus 未注册 QMetaType → 跨线程状态信号被 Qt 静默丢弃**
- 位置：`src/engine/FlowEngine.cpp:258/278/313`（工作线程 emit `toolStatusChanged(Flow*,int,ToolStatus)`）、`src/utils/Common.h:65`（`enum class ToolStatus`）、`src/app/MainWindow.cpp:72-75`
- 问题：全工程无 `Q_DECLARE_METATYPE(ToolStatus)` / `qRegisterMetaType`。工作线程→UI 线程经默认 AutoConnection 变 QueuedConnection，Qt 因参数类型未注册打印 "Cannot queue arguments of type 'ToolStatus'" 并丢弃该信号 → 流程编辑器节点状态灯永远不更新（用户看不到执行到哪一步）。
- 建议：`Q_DECLARE_METATYPE(ToolStatus)` + 首次使用前 `qRegisterMetaType<ToolStatus>()`，或将信号参数改为 `int`。

**[高] H-15 ConnectionItem 右键删除连线双重释放**
- 位置：`src/ui/FlowEditor.cpp:874-886`（`contextMenuEvent` 内 `delete this`）vs `src/ui/FlowEditor.cpp:499-505`（`clearScene` 遍历 `m_connections` 再 delete）
- 问题：右键"删除连线"后悬垂指针仍留在 `m_connections` 列表；后续 `clearScene()/refresh()` 再次 delete → 双重释放崩溃。
- 建议：删除连线时先从 `m_connections` 移除；或连线删除统一由 FlowEditor 处理（连线项只 emit 信号，不自行 delete）。

**[高] H-16 StatusPanel OK/NG 计数无限膨胀**
- 位置：`src/ui/widgets/StatusPanel.cpp:108-120`（`setStationState`）
- 问题：重复设置同一状态会重复 +1：旧状态==新状态时 `--` 分支不执行、`++` 分支却执行 → 每帧刷新同状态导致 OK/NG 总数无限增长。
- 建议：仅状态变化时调整计数（`if(old!=new){ if(old==OK)--; ... if(new==OK)++; }`）。

**[高] H-17 PropertyDialog::onTryRun 无锁改写真实工具对象 + 同步执行卡界面**
- 位置：`src/ui/PropertyDialog.cpp:197-234`
- 问题：试执行对真实 `ITool*` 临时 setProperty→execute→恢复；若 FlowEngine 工作线程正持有同一工具执行流程 → 无锁数据竞争（UI 改属性 vs 引擎读属性）；且 execute 在 GUI 线程同步跑，工具耗时即卡界面；execute 抛异常时恢复循环不执行 → 参数残留。
- 建议：试执行用工具深拷贝副本（`ITool::clone`），或经 FlowEngine 串行队列执行；恢复用 RAII guard（析构自动恢复），并 try/catch 兜底。

**[高] H-18 端口拖拽连线失效 + cancelConnectionDrag 声明无定义**
- 位置：`src/ui/FlowEditor.cpp:398`（`startConnectionDrag` 定义无调用者）、`src/ui/FlowEditor.h:196`（`cancelConnectionDrag` 仅声明）
- 问题：`PortItem::mousePressEvent` 只 accept 不启动拖拽 → 端口拖拽连线整体失效（连线只能靠代码）；`cancelConnectionDrag` 一旦被调用即链接错误。
- 建议：PortItem 按下时调用 `scene->startConnectionDrag`；补全或删除 `cancelConnectionDrag` 定义。

**[高] H-19 YoloTeachWizard 置信度格式串 bug**
- 位置：`src/ui/YoloTeachWizard.cpp:224`（`QStringLiteral("%1 %.0f%%").arg(name).arg(d.score*100)`）
- 问题：`QString::arg` 不识别 printf `%f` 格式符 → 实际显示 "类别名 %.0f%%"，第二个 arg 无 `%2` 占位被忽略 → 置信度数值永远不显示。
- 建议：`QString("%1 %2%").arg(name).arg(qRound(d.score*100))`。

### 3.5 plugins/tools 模块（子代理B，高）

**[高] H-20 SerialPort / Ethernet 释放后访问 errorString()（use-after-free）**
- 位置：`plugins/comm/SerialPort.cpp:74`（`delete port` 后 `port->errorString()`）、`plugins/comm/Ethernet.cpp:50`（`delete socket` 后 `socket->errorString()`）
- 问题：打开失败路径先 delete 再读已释放对象 → 未定义行为（必然触发路径）；Ethernet 客户端断开分支（L55-66）只断开不释放 socket 且清空上下文指针 → 泄漏，重连覆盖旧指针。
- 建议：delete 前先拷贝错误串 `QString err = port->errorString(); ... delete port;`；Ethernet 用 RAII/QPointer 管理 socket 生命周期。

**[高] H-21 UpdateView 每次 execute 泄漏 cv::Mat**
- 位置：`plugins/tools/UpdateView/UpdateView.cpp:29`（`new cv::Mat(*input)` 存 `void*` 进上下文）
- 问题：全工程无任何消费者读取该指针 → 每次执行泄漏一块 Mat，连续运行下内存持续增长；功能本身也是死功能。
- 建议：删除该段，或改为值语义并由下游真正消费/释放。
