# LW Vision 界面与交互体验排查报告

> 排查日期：2026-08-31 ｜ 排查人：AI 助手（代码静态排查）
> 范围：`src/ui`、`src/app`（Qt Widgets 中文界面，仅静态读码，未运行）
> 方法：通读主窗口/流程编辑器/图像控件/属性对话框/设置/教导向导等关键 UI 源码，逐一核对信号连接、控件实例化、数据流与高频操作路径。

---

## 一、结论摘要

LW Vision 功能体量在快速膨胀（流程编辑器、亚像素测量、AI 教导向导、PLC 模拟器、DIY 界面编辑器），但 **UI 层存在大量"看着能用、点了没反应"的死功能**，其根源不是交互设计，而是**信号未接线 / 控件未实例化 / 菜单工具栏是死代码**这三类结构性断链。当前状态是"演示壳功能多、交互闭环少"，距离"工程师日常顺畅使用"还有明显差距。

- **阻断级（P0）问题 7 项**：全部是功能点了无效或完全不显示。
- **效率级（P1）问题 5 项**：集中在"改参数→试执行→看结果"循环与图像查看体验。
- **一致性/可读性（P2）问题 8 项**：术语、图标、密度不统一。
- **细节（P3）问题 6 项**：弹窗打断、死代码、空壳控件等。

> ⚠️ 特别提醒：本次排查发现 **MenuBar.cpp / MainToolBar.cpp 是两个从未被实例化的死代码类**（编译进 VIUI 但无人 new），它们承载了撤销/重做、编辑菜单、快捷键（Ctrl+N/O/S、F5 等）——也就是说应用目前**没有任何快捷键、没有任何编辑菜单、没有撤销重做**。这是"为什么界面感觉别扭"的最大隐藏原因之一。

## 二、P0 阻断级（功能点了无效 / 界面元素不显示）

### P0-1 流程编辑器右键菜单大量功能"点了无效"（信号未接线）
- **位置**：`src/ui/FlowEditor.cpp:669-701`（右键菜单构造）、`src/app/MainWindow.cpp:205-207`（信号连接）
- **现状**：右键菜单提供了 `🔧 属性 / ✏️ 重命名 / ⬆上移 / ⬇下移 / ⏸禁用 / 📋复制 / 📌粘贴 / 🗑删除` 共 8 项。但 MainWindow 只连接了 **`toolEditProperties`（属性）** 一个信号；`toolRename / toolMoveUp / toolMoveDown / toolToggleActive / toolCopy / toolPaste / toolDelete` 这 7 个信号**发射后无人接收**，全部无效。`toolCopy/toolPaste` 还依赖的 `m_clipboardTypeName` 也从未被赋值（复制无效 → 粘贴自然无效）。
- **影响**：工程师无法重命名、排序、启停、复制、删除流程节点——最常用的流程调整操作全废。
- **建议**：在 MainWindow 中为 7 个信号逐一接线（实现对应引擎操作）；或在 FlowEditor 内部自洽实现并暴露更少的外部信号。

### P0-2 双击节点"编辑属性"无反应（信号未接线）
- **位置**：`src/ui/FlowEditor.cpp:521-523`（nodeDoubleClicked→emit toolDoubleClicked）、`src/app/MainWindow.cpp`（未连接）
- **现状**：ToolNode 双击会发射 `nodeDoubleClicked`，FlowEditor 转发为 `toolDoubleClicked`，但 MainWindow **没有连接 FlowEditor::toolDoubleClicked**（只连接了 Toolbox::toolDoubleClicked 用于"工具箱双击→添加工具"）。
- **影响**：用户双击流程节点期望打开属性——没反应。只能靠右键"属性"一项，与行业软件（CKVision 双击编辑）习惯不符。
- **建议**：`connect(m_flowEditor, &FlowEditor::toolDoubleClicked, this, &MainWindow::onEditToolProperties);`

### P0-3 Delete 键删除节点无效（信号未接线）
- **位置**：`src/ui/FlowEditor.cpp:848-855`（FlowView::keyPressEvent 发射 deleteRequested）、`src/ui/FlowEditor.cpp:471-479`（setupView 未连接 deleteRequested）
- **现状**：按 Delete 键发射 `deleteRequested`，但 FlowEditor 从未 `connect(m_view, &FlowView::deleteRequested, ...)`，已存在的 `onSceneDeleteRequested()` 槽永远不触发。
- **影响**：标准删除键失效，只能靠右键删除（而右键删除本身也因 P0-1 无效）。
- **建议**：在 setupView 中补上 `connect(m_view, &FlowView::deleteRequested, this, &FlowEditor::onSceneDeleteRequested);`，并落实 toolDelete→引擎删除。

### P0-4 主窗口"缩放"功能 100% 失效且无 UI 入口
- **位置**：`src/app/MainWindow.h:101`（m_displayArea 声明）、`src/app/MainWindow.cpp:495-509`（4 个缩放槽）、`MainWindow.cpp:163-170`（实际用的是 m_multiView）
- **现状**：
  1. `m_displayArea` 在 setupUI 中**从未被 new**（实际显示用的是 `m_multiView`/MultiViewWidget），成员始终为 nullptr，所以 `onZoomIn/onZoomOut/onZoomFit/onZoom1x1` 里的 `if (m_displayArea)` 永远不成立；
  2. 这 4 个槽**也从未被任何菜单/工具栏动作连接**——菜单与工具栏里根本没有缩放项。
- **影响**：主窗口图像区没有"放大/缩小/适配/1:1"按钮（虽然 ImageViewWidget 内部有滚轮缩放，但用户没有入口和反馈）。
- **建议**：删除 m_displayArea 死成员，把缩放槽改到 `m_multiView->viewAt(0)` 或 ImageViewWidget 实例，并在工具栏/图像区补缩放控件（或直接复用滚轮，见 P1-6）。

### P0-5 MenuBar / MainToolBar 是死代码，快捷键与编辑功能整体缺失
- **位置**：`src/ui/MenuBar.cpp`、`src/ui/MainToolBar.cpp`（编译于 VIUI，`src/ui/CMakeLists.txt:10-15`）；实际 UI 由 `MainWindow.cpp:218-356` 内联创建
- **现状**：grep 全工程无任何 `new MenuBar` / `new MainToolBar`。真正展示的菜单栏是 MainWindow 里 createMenus() 手写的（文件/设置/标注/AI/相机/操作/数据/视图/帮助），工具栏是 createToolBar() 手写的（新建/打开/保存/执行/运行/停止/扫描/相机/用户）。
- **影响**：MenuBar 中精心实现的**撤销/重做/剪切/复制/粘贴/删除/单步执行(F10)/最近项目/快捷键(Ctrl+N、Ctrl+O、Ctrl+S、Ctrl+Z、F5、F11)** 全部不可用；MainToolBar 中的**暂停(F6)/缩放下拉框(Ctrl++/Ctrl+-/Ctrl+0)** 也不可用。全应用**没有任何快捷键**。
- **建议**：二选一——(a) 废弃死代码类，在 MainWindow 手写菜单中补全编辑菜单与快捷键；(b) 让 MainWindow 改用这两个类。推荐 (a) 快速收敛，同时把 F5 运行、Ctrl+S 保存等高频快捷键补上。

### P0-6 底部"CCD 检测项目表"（DataPanel）从不更新，永远是 "--"
- **位置**：`src/app/MainWindow.cpp:182-190`（创建并加入布局）、`src/ui/DataPanel.cpp`
- **现状**：
  1. MainWindow 创建 `m_dataPanel` 后**从未调用** `setStats() / updateResult() / setStationStatus()` 任何一个；
  2. DataPanel 构造函数里 `m_summaryLabel` 声明了但**从未 new**（第 14/23 行声明，构造函数只 addWidget(m_table)），所以即便 setStats 被调用，`onStatsChanged()` 里 `if (!m_stats || !m_summaryLabel) return;` 也永远提前返回。
- **影响**：主界面下半部分的检测结果表是纯静态装饰，8 列永远显示 "CCD1..N / -- / --..."。工程师看不到每工位当前值/上下限/NG 项，只能看状态栏一个 OK/NG 数字。
- **建议**：在 flowExecuted 槽中把每个工位/结果写入 DataPanel（updateResult/setStationStatus），构造函数补建 m_summaryLabel，并连接 statsChanged。

### P0-7 状态栏"用户"与"连接"标签创建了却从未显示
- **位置**：`src/app/MainWindow.cpp:358-381`（createStatusBar）
- **现状**：创建了 `m_userLabel("用户: 管理员")`、`m_connectionLabel("未连接")`，但 addWidget/addPermanentWidget **只加入了** statusLabel、fileLabel、okCount、ngCount、yield、cameraLabel——用户标签和连接标签从未加入状态栏。
- **影响**：登录后看不到当前角色（applyUserRole 里 setText 也无处显示）；相机连接状态也看不到（onScanCameras 里设置 m_connectionLabel 但用户不可见）。
- **建议**：把这两个 label 加入状态栏（如 `statusBar()->addPermanentWidget(m_userLabel)`），并让相机/连接状态驱动它。

## 三、P1 效率级（高频操作不顺畅）

### P1-8 连续运行时图像每帧重置缩放/平移，无法放大观察
- **位置**：`src/ui/widgets/ImageViewWidget.cpp:23-28`（setImage→fitToWidget）、`src/ui/widgets/MultiViewWidget.cpp:68-74`
- **现状**：每次新帧 `setImage()` 都调用 `fitToWidget()`，强制"适应窗口"并把 m_offset 归零。连续运行（或虚拟相机回放）时，用户刚放大想细看某处缺陷，下一帧就被打回全景。
- **影响**："放大→细看→再放大"在运行中完全不可用，工程师只能停止运行后再看，打断检测节奏。
- **建议**：首次显示/用户手动"适配"时才 fitToWidget；新帧到达时保持当前缩放与平移（仅当首次或显式请求时适配）。

### P1-9 图像区没有像素坐标/缩放比例/网格反馈（cursorImagePos 信号未用）
- **位置**：`src/ui/widgets/ImageViewWidget.h:58`（cursorImagePos 信号）、全工程无连接
- **现状**：ImageViewWidget 在鼠标移动时发射 `cursorImagePos(图像坐标)`，但**没有任何人连接**该信号；也没有缩放比例显示、网格/标尺、像素值读取。MultiViewWidget 视图标题只有固定 "CCD1..N"。
- **影响**：定位缺陷坐标、核对缩放比例这些测量场景高频操作只能靠目测，缺乏量化反馈。
- **建议**：把 cursorImagePos 接到状态栏（显示图像坐标+RGB 值），状态栏加缩放百分比；标题用工位名（setTitle 从未被调用）。

### P1-10 关闭窗口无"未保存"提示，配置易丢失
- **位置**：`src/app/MainWindow.cpp:866-871`（closeEvent）
- **现状**：closeEvent 直接 `saveSettings()` 后 accept，从不检查 `m_projectMgr->isModified()`，也不提示保存项目。
- **影响**：工程师调了半天参数/流程，随手关窗口直接丢，工业软件的大忌。
- **建议**：closeEvent 中若 m_modified 弹"是否保存"三选（保存/不保存/取消）；标题栏加未保存 "*" 标记。

### P1-11 多视图布局固定、无分屏切换入口，且只有视图 0 被更新
- **位置**：`src/app/MainWindow.cpp:167-170`（按 cameraCount 一次性 setLayout）、`MainWindow.cpp:834-848`（只 setImage(0)）
- **现状**：多视图布局仅在启动时按相机数设置一次，运行时没有任何 UI 切换 1/2/4/8 分屏；且 `onCameraImageReceived` / flowExecuted 只写 `view 0`，其余视图永远是空。
- **影响**：8 工位场景下看不到多路画面，多视图名存实亡。
- **建议**：视图菜单加分屏切换（1~8）；按工位/相机号分别写入对应视图。

### P1-12 试执行页"看结果"依赖最近一帧，无法用真实流程链预览
- **位置**：`src/ui/PropertyDialog.cpp:174-194`、`197-234`（onTryRun）
- **现状**：试执行只用 `m_lastImage`（对话框打开时的最近一帧）对**单个工具**跑，不执行其上游工具链，也不解析 `$(工具名.键)` 数据链接；NG 工具的正确叠加需要依赖前序工具输入。
- **影响**："改参数→试执行→看效果"循环对依赖链路的工具（找圆→补正→检测）不成立，试执行结果可能与真实流程不符。
- **建议**：试执行时沿 toolIndex 之前的链路从最近帧顺序执行（或执行一个只读副本流程），叠加显示时同时渲染各步结果。

## 四、P2 一致性与可读性

### P2-13 术语/文案不统一
- 运行命令：菜单"执行程序/运行程序/停止程序"（MainWindow.cpp:251-253）vs 工具栏"执行/运行/停止"（339-344）vs 死代码 MainToolBar"开始/停止/暂停"。
- "相机/工位数量(重启生效)"（SettingsDialogs.cpp:61）vs "工位名称"（63）vs 状态栏"相机: 无"。
- 建议：统一为"运行/停止"、"工位/相机"一套术语；操作级动作（运行/停止）在菜单、工具栏、快捷键三处一致。

### P2-14 图标风格不统一（emoji vs 矢量图标）
- 位置：`src/ui/FlowEditor.cpp:669-701`（右键菜单用 🔧✏️⬆⬇📋📌🗑）、MainWindow 工具栏用 `IconHelper` 矢量图标、菜单无图标。
- 影响：同一产品两种图标体系，深色背景下 emoji 渲染风格（Win10 等）不一，观感廉价。
- 建议：统一使用 IconHelper 或一套 QSS 图标；菜单/右键菜单也用相同来源。

### P2-15 DataPanel 列宽固定、信息密度与"良率"列意义弱
- 位置：`src/ui/DataPanel.cpp:38-51`
- 现状：8 列全 Fixed（总宽 580px），窗口缩小时无横向滚动适配；"良率"列每次只显示 100%/0%（对单条结果无意义）；颜色只区分 OK/NG 文本。
- 建议：检测项目列 Stretch、数值列紧凑；良率列显示该工位历史累计良率；用单元格背景色增强 OK(绿)/NG(红) 可读性。

### P2-16 状态可见性弱：运行状态仅一条文本、日志默认隐藏
- 位置：`MainWindow.cpp:195`（日志 dock 默认 hide）、`MainWindow.cpp:133-136`（运行状态仅 setText）
- 现状：运行/停止只在状态栏一小段文字；日志面板默认隐藏，错误提示基本不可见。
- 建议：运行状态用颜色化标签（运行=绿/停止=灰/NG 闪烁红）；日志 dock 默认展开或提供明显的角标提示；把 Logger 的输出接入 LogPanel。

### P2-17 属性对话框参数页无分组折叠、工具说明缺失
- 位置：`src/ui/PropertyDialog.cpp:101-158`
- 现状：参数用 QFormLayout 平铺，group 仅作文本后缀 `[组]`；无参数含义 tooltip、无"帮助"说明。
- 影响：40+ 工具的参数含义只能靠猜，新手无从下手。
- 建议：按 def.group 用 QGroupBox 分组；label 加 tooltip 展示参数说明；增加"使用说明"页签或帮助按钮。

### P2-18 系统设置"界面语言"为假选项
- 位置：`src/ui/SettingsDialogs.cpp:32-35`
- 现状：下拉"简体中文 / English (敬请期待)"，但 onAccept 从未应用 language，切换无效。
- 建议：要么实现语言切换，要么去掉该项，避免"看着能选、实际无效"。

### P2-19 无统计复位、无历史明细入口
- 位置：`MainWindow.cpp:376-380`（OK/NG 计数）
- 现状：状态栏 OK/NG/良率为累计值，无"清零"按钮；CSV 导出在"数据"菜单但无入口提示历史记录。
- 建议：数据菜单增加"清零统计"；把历史记录做成可滚动表格视图（现有 GlobalStats::history 未被 UI 展示）。

### P2-20 状态提示滥用模态弹窗
- 位置：`MainWindow.cpp:642-647`（"没有可执行的流程"用 QMessageBox::information）
- 影响：每次误触"执行"都弹窗打断，高频场景很烦。
- 建议：非致命提示改为状态栏/日志短提示，仅错误用弹窗。

## 五、P3 细节与死代码

### P3-21 DisplayArea 类整体未使用（被 MultiViewWidget 取代）
- 位置：`src/ui/DisplayArea.cpp`（编译进 VIUI，MainWindow 未引用）
- 建议：删除或改造成可复用组件，避免后续维护混淆。

### P3-22 ButtonWidget/StatusWidget/ImageWidget/ValueWidget 是空壳
- 位置：`src/ui/widgets/ButtonWidget.*`、`StatusWidget.*`、`ImageWidget.*`、`ValueWidget.*`（头文件只有注释"后续实现"+空类）
- 建议：与 UIEditor/DIY 运行界面规划对齐，要么实现要么从构建中移除，避免误导。

### P3-23 UIEditor 撤销/重做为空实现，但按钮存在
- 位置：`src/ui/UIEditor.cpp:834-843`
- 现状：`undo()/redo()` 空函数，`canUndo/canRedo` 恒 false，工具栏"↩撤销/↪重做"按钮点击无任何效果。
- 建议：删除按钮或接入 QUndoStack。

### P3-24 流程编辑器节点位置不持久化
- 位置：`FlowEditor::onNodeMoved`（注释"此处可扩展为保存节点位置到配置"）
- 现状：每次 refresh() 都 autoLayout 重新排布，用户拖动的节点位置在刷新/重开后丢失。
- 建议：把节点坐标写入 Flow JSON（vipj），加载时恢复。

### P3-25 状态栏不显示当前活动工具/当前执行步骤
- 位置：`MainWindow.cpp`（toolStatusChanged 只刷新节点颜色）
- 现状：流程执行到哪一步只能看节点小圆点颜色，状态栏无"正在执行：找圆(第5步)"这类信息。
- 建议：flowExecuted/toolStatusChanged 时更新状态栏"正在执行：xxx"。

### P3-26 教导向导顶部提示过长挤占空间
- 位置：`src/ui/TeachWizard.cpp:63`
- 现状：`①连接相机并摆正工件 ②抓取样帧 ③标记OK/NG ④训练 ⑤检测` 一行全塞，缩小窗口会截断。
- 建议：拆成步骤条组件或换行。

## 六、高频操作路径评估（工程师视角）

| 操作循环 | 现状 | 卡点 |
|---|---|---|
| 从模板新建 → 添加工具 → 配参数 → 试执行 → 看结果 | 流程长、可走通 | 添加工具后自动弹属性框（好的）；但双击改属性无效(P0-2)、右键大部分无效(P0-1)、试执行不跑链路(P1-12) |
| 运行 → 连续检测 → 放大看缺陷 | 图像区能看但难用 | 每帧重置缩放(P1-8)、无坐标/缩放反馈(P1-9)、多视图只有一路(P1-11) |
| 调整参数 → 重新试执行 | 依赖单帧 | 试执行结果与真实链路可能不符(P1-12) |
| 查看判定结果/测量数据 | 严重不足 | 数据表不更新(P0-6)、历史无界面展示(P2-19)、良率列无意义(P2-15) |
| 保存/退出 | 有风险 | 无未保存提示(P1-10)、无快捷键(P0-5) |
