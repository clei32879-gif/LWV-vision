## 阶段1：运行时架构正本清源（无硬件可做，预计先行）

**目标**：软件从"演示壳"变成"正确的工业软件架构"。

1. **执行引擎多线程化 + 双层图架构**（参考 `docs/OpenIVS专项评估.md`）
   - 现状：`FlowEngine::executeOnce` 在 UI 线程执行，相机 `grabFrame(1000)` 阻塞界面；节点连线不真正传数据
   - 改造：参照 OpenIVS 的双层设计——**算法流水线图（Flow）**与**设备编排图（Sequence：相机触发/PLC/显示）**分离；节点异步执行（分叉汇聚 WaitAll/WaitAny、嵌套流程 RunFlow），检测流水线在 worker 线程，UI 只收信号
   - 验收：连续运行时拖动窗口/点菜单不卡顿；停止响应 < 200ms；分叉流程可并行跑
2. **虚拟相机驱动**（无真机也能开发演示的关键）
   - 实现 `ICameraDriver` 的 `VirtualCamera`：图像文件夹轮询 / 定时循环回放 / 参数化生成图
   - 验收：不接任何硬件，扫描→打开→采集→检测全流程可跑
3. **PLC 模拟器**
   - 内置 Modbus TCP slave 模拟器（或模拟 PLC 驱动），读写寄存器、回写 OK/NG 计数
   - 验收：Modbus 读/写工具节点对模拟器收发正常
4. **补齐"待实现"功能**
   - 系统设置、项目设置、全局变量管理、切换用户（三级权限生效）
5. **项目保存/加载真正闭环**
   - 流程结构 + 每个工具属性 + 界面布局 + 标定数据 全部序列化（.vipj）
   - 验收：保存→重启→加载后一切如初

## 阶段2：通用工具打磨到"能用好用"（对标 CKVision 的工具质量）

1. **算法质量**：边缘亚像素化、圆/线鲁棒拟合（RANSAC）、自动阈值策略、ROI 随定位结果跟随
2. **数据流打通**：找圆→位置补正→后续工具 ROI 自动跟随（这是 CKVision 流程的灵魂，目前节点连线并不真正传数据）
3. **结果可视化**：每个工具在图像上叠加 ROI/检测图形/OK/NG 标注，颜色可配置
4. **图像查看器升级**：缩放/平移/网格/标尺/像素信息，多画面布局 1~8 分屏
5. **逐工具验收表**：40+ 工具每个都用标准图片库回归验证，结果记录在案

## 阶段3：螺纹检测专项（拳头功能）

按需求文档 4.2 规格实现：螺纹展开（极坐标展开成直纹面）→ 牙距/牙数统计 → 烂牙/缺牙/毛刺/斜牙判定 → 牙外径测量；配套专用教导界面与样本图库。

## 阶段4：AI 检测能力（对标 DLCV.AI / 视觉芯，"像人眼一样找缺陷"）

1. **ONNX Runtime 推理节点**：C++ 端封装（CPU 为底线，显卡可选加速），支持 YOLOv8 检测/分类/分割三类模型，输入输出对齐 OpenCV Mat；接口形状与 JSON 结果语义**对齐 OpenIVS 标准**（`category_id`/`box`/`angle`/`region`/`mask_rle` + 耗时信息，见 `docs/OpenIVS专项评估.md`）
2. **标注-训练闭环**：软件内简化标注（矩形/多边形）→ 一键调用训练（Python 脚本，YOLOv8/分类迁移学习）→ 导出 ONNX → 回到软件推理；学 DLCV"标训测部一体"，避免视觉芯"双软件断链"的坑
3. **无监督异常检测节点**：纯 OK 图即可用（PaDiM/PatchCore 路线，anomalib 导出），解决"NG 样本难收集"的工业痛点
4. **硬件定位（已确认）**：部署/训练机显卡上限按 **RTX 3060（桌面版 12GB）** 档设计
   - 推理：CPU EP 为底线（无卡可跑），检测到显卡自动走 CUDA EP，进阶可切 TensorRT EP
   - 估算余量：YOLOv8s@640 约 50~150 FPS，覆盖 8 相机 × 5 张/秒（300颗/分钟满配）仍有富余；阶段4 立项后用真实模型跑基准核实
   - 训练：100 张图迁移学习微调为分钟级，支撑"30分钟从标图到上线"目标
   - 部署注意：CUDA/cuDNN 运行库随安装包管理；产线机关闭显卡驱动自动更新；GPU 调用设超时保护
5. **验收**：零基础用户 30 分钟内完成"标 100 张图 → 训练 → 上线检测"全流程

## 阶段5：通讯与整机闭环（等真机到位）

信捷 XD3 Modbus TCP/RTU 真机联调、拍照触发→检测→吹气 IO 时序、伺服转速联动、1~8 相机即插即用、异常恢复与看门狗。

## 阶段6：平台化与商业交付

## 横切原则（每个阶段都遵守）

- **每步可运行**：每个阶段结束程序必须能编译运行，能演示
- **测试资产**：建立标准测试图片库（OK/NG 样本），每阶段跑回归
- **git 规范**：小步提交，功能分支，定期 push 远端
- **文档同步**：每阶段更新对应文档，不留"三个盘符三个故事"的历史问题
- **范围控制**：一次只推一个阶段，做完验收再进下一阶段

## 风险与对策

| 风险 | 对策 |
|------|------|
| 移动硬盘是唯一副本 | 尽快建远端私有仓库（Gitee/GitHub） |
| 无硬件开发，真机适配可能返工 | 虚拟相机/模拟PLC先行，驱动接口保持 ICameraDriver/IPLCDriver 抽象不变 |
| 范围大（平台+AI+专项），易烂尾 | 严格按阶段推进，每阶段有明确验收标准 |
| AI 训练依赖 Python 环境 | 训练侧独立打包（训练机可选），部署机只带 ONNX Runtime 推理 |
