# 零维视界（LW Vision）：一个融合传统视觉算法与深度学习的开放式通用工业机器视觉检测平台

> 技术报告 ｜ 2026-09
> 关键词：机器视觉；缺陷检测；流程化工具链；YOLOv8；无监督异常检测；Modbus；GigE Vision

## 摘要

工业制造对表面缺陷检测、尺寸测量与定位引导的需求持续增长，而商用视觉软件（如 CKVisionBuilder、VisionMaster）存在价格高昂、扩展封闭等问题，开源方案（如 OpenIVS）则多停留在框架层面、工程完成度不足。本文介绍我们研发的 LW Vision——一个运行于 Windows 平台、以 C++17/Qt6/OpenCV 5/ONNX Runtime 为技术栈的通用工业机器视觉检测平台。系统以"流程化工具链"为核心范式，提供覆盖图像采集、预处理、定位补正、检测识别、几何测量、逻辑控制、设备通讯、数据管理的 90 个检测工具；在 AI 方面实现了 YOLOv8 有监督检测/分类与 anomalib 无监督异常检测双路线的端到端训练-部署闭环；在设备层实现了兼容 GigE Vision 协议的自研相机驱动（免厂商 SDK）与覆盖信捷 PLC 真机契约的 Modbus TCP/RTU 双通道通讯。系统经合成图库（494+ 项自动回归）、MVTec AD 公开数据集及真实产线图像三类基准验证，并在软件工程层面建立了授权管理、设备模板、SQLite 检测记录与 DIY 运行界面等商用化配套设施。实测表明，本平台在单帧 CPU 推理 52ms 的条件下可支撑多工位筛选机典型节拍，直接 GPU 加速（DirectML）可降至 41ms。

## 1. 引言

机器视觉是智能制造质量控制的核心手段。当前工厂获取视觉能力有三条路径：采购国际商用软件（HALCON + 自研上位机，成本高）、采购国产整合软件（CKVisionBuilder、海康 VisionMaster 等，闭源且按模块收费）、或基于开源库自研（开发门槛高、周期长）。国内中小设备商与工厂自动化部门普遍面临"商用软件买不起、自研周期等不起"的困境。

现有开源方案中，OpenIVS（.NET/WPF）提供了较好的架构参考，但工具数量与工程完成度距离产线可用仍有差距；MIP 等个人开源框架则缺乏持续性维护。另一方面，深度学习在工业检测中的落地仍存在"训练平台与推理软件割裂"（标注、训练在 Python 生态，部署在 C++ 上位机，两者断链）的普遍痛点。

针对上述问题，我们研发了 LW Vision，其设计目标为：

1. **工具链完整性**：对标商用软件的工具覆盖面，单平台提供从取图到通讯的全流程工具；
2. **AI 可用性**：标注、训练、导出、部署全链路打通，AI 功能"真的能用"而非演示原型；
3. **设备开放性**：相机接入不绑定厂商 SDK，PLC 通讯兼容真实产线契约；
4. **商用可交付**：授权、安装、数据持久化、多工位管理等工程设施齐备。

## 2. 系统架构

### 2.1 总体分层

系统分为五层：

- **硬件抽象层（HAL）**：ICameraDriver（相机）、IPLCDriver（PLC）、IServoDriver（伺服）、IIODriver（IO）四个抽象接口。相机驱动含自研 GigE Vision 驱动（GVCP 控制协议 + GVSP 流协议，免厂商 SDK）、Basler Pylon 驱动、度申 DVP2 驱动与虚拟相机；PLC 驱动基于自研 Modbus TCP/RTU 主站实现。
- **引擎层**：ITool 工具基类（属性自描述 + 反射式注册）、FlowEngine 流程引擎（QtConcurrent 多线程执行、消息驱动跳转、执行互斥）、ToolContext 执行上下文（命名图像槽、`$(工具名.键)` 数据流引用解析、全局变量）。
- **插件层**：90 个工具以静态插件形式注册，CMake 聚合链接。
- **UI 层**：节点式流程编辑器、属性对话框（四页签：基本/参数/数据判定/试执行）、图像查看器（缩放平移 + ROI 图形化拖拽编辑 + 检测结果叠加）、数据面板、历史查询、DIY 运行界面渲染器。
- **数据层**：工程文件（.vipj, JSON）、SQLite 检测记录库、设备模板库、授权文件。

### 2.2 流程引擎

流程为工具的有序序列，引擎以工作线程逐工具执行，支持三种控制流：(1) 消息驱动跳转——工具执行后可写入消息码，引擎据此实现循环回跳、条件退出与无条件跳转，支撑循环、选择分支等结构化控制；(2) 子流程调用——执行流程工具按名调用其他流程，共享上下文，带递归深度防护；(3) 条件跳转——数据表达式判定后按 case 分发。所有结构变更基于工程级快照实现撤销/重做（上限 50 步）。

数据流采用命名空间引用机制：每个工具执行后结果以"工具名.键"写入全局命名空间，后续工具的字符串属性可经 `$(工具名.键)` 引用解析（RAII 保障），配合"位置补正→ROI 跟随"机制实现定位-检测链的数据闭环。

### 2.3 工具体系

90 个工具按十类组织：相机/图像源（3）、检测识别（26）、几何测量（11）、定位补正与标定（12）、图像处理（10）、逻辑控制（17）、文件通讯（11）。其中检测类工具基于自研亚像素边缘库（双线性采样 + 梯度峰值抛物线内插 + 鲁棒圆/直线拟合）实现 0.1px 级测量精度；螺纹检测采用极坐标展开 + 环带角度投影管线，实现牙数/缺牙/烂牙/毛刺/斜牙的专项判定。全部工具带中文一句话描述（悬浮提示/搜索可达），属性经"死属性清零"审计确保声明即生效。

## 3. AI 检测子系统

### 3.1 有监督路线

推理端基于 ONNX Runtime 封装（CPU EP 为底线，DirectML EP 提供任意 DX12 显卡加速，实测 YOLOv8n@640 CPU 52ms / GPU 41ms），支持 YOLOv8 检测与分类两类模型及 letterbox 预处理对齐。工程层实现：

- **训练闭环**：内置标注工具（YOLO 格式导出）→ ultralytics 训练 → ONNX 导出 → 软件加载，避免"双软件断链"；
- **商用级判定**：目标类别过滤（忽略良品类）、数量区间判定（漏检/多检均 NG）、单帧耗时与执行设备输出；
- **模型全局缓存**：同路径模型多工具节点共享会话。

### 3.2 无监督路线

集成 anomalib（Padim/PatchCore/EfficientAd），实现"纯 OK 图训练"范式。我们解决了工程落地中的一个关键问题：anomalib 2.x 的 ONNX 导出会将归一化与裁剪后处理固化进模型，导致 OK/NG 分数全部饱和为 1.0——解法为导出前动态摘除后处理器，使模型输出原始异常分数，判定阈值经 F1 最优化搜索后写入元数据供 C++ 端使用。训练脚本内置圆对齐预处理与自动化验证报告。

### 3.3 实验验证

在三类基准上进行了系统验证（方法与结论以实践为准绳）：

1. **合成图库**：48 张螺纹图（OK 24 + 四类 NG 各 6），快速找圆 48/48，亚像素半径误差 ≤0.87px；螺纹检测牙数 24/24 全对、缺牙检出 6/6。
2. **MVTec AD（screw 类）**：320 张训练 OK 图，测试集 AUROC 0.66~0.75（受输入尺寸与验证协议影响），验证了无监督管线在标准非周期纹理数据上的可行性。
3. **真实产线数据**：螺钉头顶视图 207 张（6 类缺陷 + 良品）。（a）无监督路线（Padim/PatchCore，含纯净子集与弱污染协议共四轮）均不可分（AUROC 0.36~0.49），根因为"开裂/发黑类缺陷与正常纹理在浅层特征空间相近"，此结果与文献中无监督方法对"语义型缺陷"失效的报道一致，亦与合成螺纹相位问题互证；（b）有监督分类路线（YOLOv8n-cls，263 张 7 类）达到 Top-1 79.7%，验证了"该类数据应走有监督"的路线判断。
4. **公开木材数据集**：东北林业大学水性漆木材缺陷数据集（335 张产线实拍，Nature Sci. Data 2025）四轮实验（Padim/PatchCore × 纯净/弱污染协议）AUROC 0.36~0.49，进一步确证**拍摄一致性是无监督落地的前置条件**（固定工位 + 固定光源 + 纯 OK 图 50+）。

上述实验中"失败"的记录均完整保留并文档化——我们认为明确无监督方法的适用边界（纹理可分、采集一致）与明确其成功同样具有工程价值。

## 4. 设备通讯与多工位系统

### 4.1 自研 GigE Vision 驱动

不依赖厂商 SDK，直接实现 GVCP（UDP 3956，设备发现/寄存器读写/心跳）与 GVSP（图像流）协议，兼容所有 GigE Vision 标准相机。针对多网口工控机的典型问题（多网卡子网路由），实现了相机 IP 与本地网卡的同段自动匹配。相机参数（曝光/增益/分辨率/触发/像素格式）经标准寄存器在线读写，分辨率变更自动执行停流-写入-恢复时序。

### 4.2 PLC 契约与多工位

以真实筛选机 PLC 程序逆向确认的寄存器契约（上位机命令 D6、产量统计 HD170~176、相机位置 HD200~214、手动拍照 M121~135、剔除 M116/117、相机使能 HM1~8 等，D 类寄存器 Modbus 直连）内置于 PLC 联动工具，13+ 种操作覆盖 启停/产量/拍照/剔除/速度/使能/吹气参数/报警延时/轴点动 全链路。配合内置 PLC 模拟器（TCP/RTU 从站 + 契约地址预设表），可脱离硬件完成全套联动调试。8 相机位为容量上限而非必须：工位可独立启用/禁用（禁用即断开且退出检测链），适配"标配 N 台、按单启用"的真实生产形态。

## 5. 商用化工程设施

- **授权系统**：机器码（CPU+卷序列号+MAC 的 SHA-256）+ RSA-2048 签名授权文件（Windows CNG 实现，零第三方依赖），模块开关（AI/相机数）构成定价分级；试用期 30 天全功能，过期降级不断产（水印 + AI 模块停用），符合工业现场"断产即灾难"的容错要求。
- **设备模板系统**：筛选机/贴标/计数/木业四类内置模板 + 用户自定义模板库，工程经验一键复用。
- **数据持久化**：检测记录 SQLite 落库（时间戳/总结果/逐项判定/数值 JSON），历史查询支持时间与 OK/NG 过滤、CSV 导出、保留期清理。
- **DIY 运行界面**：布局编辑器所见即所得，运行时渲染器将布局实例化为操作员界面（实时图像/结果表/绑定键数值/操作按钮/工位状态灯）。
- **交付形态**：自包含便携包（windeployqt + OpenCV + ONNX Runtime，213MB）与 Inno Setup 安装包双形态。

## 6. 质量保障

- **自动化回归**：17 项 ctest 套件，其中工具回归 506 项检查覆盖全部检测工具的合成图验证；引擎测试覆盖循环/分支/子流程/脚本控制流；Modbus TCP/RTU/契约全链路联测（虚拟串口线）；工程存取往返测试。
- **线程安全**：工具属性与结果的读写锁、执行互斥、关停等待序列化，经并发压力测试。
- **死属性审计**：全部 90 工具的属性声明-消费一致性核查，14 处不一致已清零。

## 7. 结论与展望

LW Vision 实现了"工具链完整、AI 双路线可用、设备契约真实、商用设施齐备"的通用工业视觉平台，全部核心代码自研并开源托管。当前限制与后续方向：(1) 无监督检测已明确适用边界，待产线固定工位数据验证落地；(2) 相机多品类（线扫/3D/红外）接口层已就绪，驱动实现依赖对应硬件；(3) 远程日志与升级、加密狗授权留待真机交付阶段。
