# LW Vision 立维视觉 — 工控机部署指南

> 目标：在没有任何开发环境的 Windows 10/11 x64 工控机上，从发布包直接运行。

## 一、快速部署（5 分钟）

1. 拷贝整个 `发布包\LWVision\` 文件夹到工控机（U盘/网络均可）
2. 双击 `LWVision.exe` — 无需安装任何运行库（MinGW 运行库已随包）

### 包内容清单

| 内容 | 说明 |
|------|------|
| `LWVision.exe` + Qt DLL | 主程序与界面运行库 |
| `libopencv_*.dll` | 图像处理（亚像素测量/螺纹检测） |
| `onnxruntime.dll` | AI 推理（CPU 版，所有 x64 CPU 可用） |
| `models/*.onnx` | AI 模型（通用预训练 + 自训缺陷分类器） |
| `testdata/` | 虚拟相机测试图 + 真实样本图 |

## 二、相机接入

| 场景 | 操作 |
|------|------|
| 度申相机 | 先装 **DVP2 SDK**（度申官网），软件自动识别；GigE 相机需与网卡同网段（前三段一致末位不同），**开巨型帧**，包大小 8000+ |
| 海康/巴斯勒 | 驱动接口已预留，插件接入中 |
| 无相机演示 | 相机菜单 → **使用虚拟相机**（自动回放测试图） |

### 多相机注意（现场经验）
- 多台 GigE 相机分网段错开；**避免同机装多品牌相机驱动**（互相干扰）
- 运动中拍照拖影 = 曝光时间与速度不匹配
- 丢帧（图像白色横条）= 网络带宽/巨型帧问题

## 三、AI 检测使用

1. 流程编辑器拖入 **AI检测** 节点
2. 模型路径填 `models\缺陷分类.onnx`（自训缺陷分类器）
3. **良品类别** 填 `良品`，最低置信度建议 0.5
4. 执行：检出缺陷类别 → NG；良品 → OK；结果叠加在图上

### 训练新模型（在装有 Python 的机器上）
```bash
# 1. 标注: 软件菜单[标注]→缺陷标注工具, 框选缺陷保存
# 2. 组织数据: python tools/prepare_cls_dataset.py <输出目录> <图库目录...>
# 3. 训练:    yolo classify train data=<输出目录> model=yolov8n-cls.pt epochs=100 imgsz=224
# 4. 导出:    yolo export model=runs/../best.pt format=onnx imgsz=224
# 5. 把 best.onnx + classes.txt 放入 models\ 即可在软件中使用
```

## 四、产线运行建议

- **开机自启**：任务计划程序设"用户登录时"启动（延迟 30 秒），工程文件放 `LoadPath.ini` 模式自动加载（规划中）
- **杀毒软件**：将 LWVision.exe 加入信任列表（避免误杀）
- **单实例**：软件重复启动会提示（规划中），现场避免多开
- **项目备份**：.vipj 工程文件定期备份（软件自动生成 .bak，规划中）
- **显卡驱动**：产线机关闭 Windows 自动更新驱动；有 N 卡想用 AI 加速另装 CUDA 运行库（当前 CPU 推理已满足 300颗/分钟）

## 五、常见问题

| 现象 | 处理 |
|------|------|
| 双击无反应 | 缺 VC 运行库的少见环境装 [VC++ 2015-2022 Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| AI 检测报"模型加载失败" | 检查 models\ 下 onnx 文件存在；**确认系统里没有被别的软件塞的旧版 onnxruntime.dll**（System32 检查） |
| 找不到相机 | 看二节 IP 规范；度申 SDK 装了吗；驱动与相机固件匹配 |
| 软件启动报加密/H0031 类错误 | 那是别家软件的加密狗服务冲突，停掉对应服务 |
