# PCIE-N1616 数字量 I/O 卡替代硬件选型调研报告

> 调研对象：8 工位转盘筛选机视觉电脑（LW Vision，C++/Qt，Windows）→ 信捷 XD5-48T-E PLC 的 16 路 OK/NG 结果信号传输
> 调研日期：2026-08-30 ｜ 报告语言：中文 ｜ 资料来源：厂商官网公开产品页 + 官方数据手册（均经在线验证可访问）

---

## 一、需求重述

- **现状**：视觉电脑（LW Vision 软件）完成 8 个工位相机检测，产生 8×（OK/NG）= **16 路数字量结果**，需实时送到信捷 XD5-48T-E PLC 的输入点 **X7 ~ X26**（16 路，24V DC 光电隔离输入），PLC 梯形图据此判定位 OK/NG 并驱动后续分拣动作。
- **原方案**：自产 PCIe 卡 **PCIE-N1616**（沁恒 CH367L 芯片，CC1616.dll 驱动：`CC1616_OpenDevice` / `CC1616_DO` / `CC1616_DO_Bit`），16 路光电隔离输入 + 16 路光电隔离输出，输出为 **NMOS 开漏（sink），500mA/通道**，DB37 接线板。该卡**目前无货**。
- **替代硬性指标**：
  1. **16 路数字量输出（DO）为必须**（8 相机 × OK/NG）；
  2. 输出形式最好是**隔离型开漏（sink）**，与 N1616 电气特性一致、与原接线方式兼容；
  3. 厂商官方资料（产品页 + 数据手册）公开可查；
  4. 采购容易、供应链稳定；
  5. 最好兼顾 16 路 DI（N1616 原为 16+16，若 DI 不需要可放宽）。
- **可选两条技术路线**：类别 A＝Modbus RTU/TCP 远程 I/O 模块（PC 经串口/以太网写 DO，无需板卡驱动）；类别 B＝本地 PCIe/USB 数字量 I/O 卡（保留板卡形态，DLL/API 驱动）。

## 三、深度对比

### 3.1 通道数：谁真正满足"16 路 DO"？

| 器件 | 实际 DO 数 | 是否满足 16DO | 备注 |
|---|---|---|---|
| **I-8057 / ET-7042 / PET-7042** | **16** | ✅ | 单模块即满足，且为隔离开漏（sink），与 N1616 电气特性一致 |
| **I-8056** | **16** | ✅ | 16DO 但**非隔离**（PLC 输入端自带 24V 光隔，见 3.3 分析） |
| ADAM-4055 | 8 | ❌ | 中文宣传"16-ch 隔离数字量 I/O"＝8DI+8DO 合计 16；**DO 仅 8 路**，需 2 台才够 16DO |
| ADAM-4056SO | 12 | ❌ | 12 路 Source 型 DO，不足 16 |
| ADAM-6052 | 8 | ❌ | 8DI/8DO Source 型 |
| I-8055 | 8 | ❌ | 8DI/8DO |
| PCI-1756 / USB-4751 | 64 / 48（可配） | ✅ | 通道充足，但属板卡路线 |

> **结论先行**：在"Modbus 远程 I/O 单模块"这一用户首选类别里，**真正 16 路 DO 的只有 ICP DAS I-8056 / I-8057 / ET-7042 / PET-7042**。研华 ADAM-4055 / 4056SO 均不满足 16DO，只能作为"需要兼带 DI 且愿用两台模块"的组合方案。

### 3.2 输出形式与 PLC 输入匹配性

- 原 N1616 输出 = **NMOS 开漏（sink）**，通过公共 +24V 和 DO.GND 驱动 PLC 光隔输入（sink 输入接线）。
- **I-8057 / ET-7042（Sink 开漏）**：与 N1616 完全同型，接线方式（DO.PWR→+24V、DOx→PLC X、DO.GND 共地）可直接沿用，**兼容性最好**。
- **I-8056（Sink 开漏，非隔离）**：输出电路同型，仅缺模块级隔离。
- **ADAM-4056SO / ADAM-6052（Source 源型）**：输出高电平（VCC 侧），驱动 PLC 输入需改用 **PNP/source 接线**（公共端接 0V），与现有 N1616 接线习惯不同，改线成本高。
- 负载能力：I-8057/ET-7042 100mA/ch，远超 PLC 单输入典型功耗（24V 光隔约 7~10mA），可靠驱动。

### 3.3 隔离问题专项评估

- **N1616**：DO 侧光隔（卡级隔离）。
- **I-8057 / ET-7042**：3750VDC 场-逻辑隔离（I/O 与模块控制电路之间），与 N1616 同级。
- **I-8056**：无模块隔离（仅 4kV ESD）。但——**信捷 XD 系列输入点本身为 24V DC 光电隔离**（X7~X26 属光隔输入，现场侧与 PLC 内部隔离），因此"信号源侧非隔离 + PLC 侧隔离"在工程上仍成立：即使模块侧与 PLC 共地异常，PLC 输入光耦仍能阻断干扰进入 PLC 内部。**故 I-8056 作为低成本备选可接受**，但推荐优先 I-8057/ET-7042 以获得双端隔离。

### 3.4 通信协议与编程方式

| 器件 | 协议 | 上位机编程方式 |
|---|---|---|
| I-8057 / I-8056 / I-8055 | Modbus RTU（RS-485，ASCII 也支持） | PC 插 USB-485 转接器，用任意 Modbus 客户端库写保持寄存器（DO 对应 0x/Coil 或 4x 区，按手册映射）；LW Vision（Qt）可加 `QModbusRtuSerialMaster`（Qt SerialBus 模块，**无需新增第三方库**） |
| ET-7042 / PET-7042 | **Modbus TCP / UDP（端口 502，内置 Web 配置页）** | PC 直接用以太网，`QModbusTcpClient` 写线圈/寄存器；无 RS-485 布线、无驱动安装、可远程 Web 配置，**编程最简单** |
| PCI-1756 / USB-4751 | 板卡本地总线 | 需安装研华 DAQNavi/D2K 驱动，调用 `AdvDIO`/`D2K_*` API（官方提供 VC/C++ 示例），**需重新开发驱动层代码**（替换 CC1616.dll） |
| ADAM-4055/4056SO/6052 | Modbus RTU / TCP | 同上 Modbus 客户端方式 |

## 四、明确推荐结论

### 推荐首选（若只选一个替代 N1616 驱动 PLC X7-X26）：

# 🏆 ICP DAS ET-7042（16 路隔离开漏 DO，Modbus TCP）

**理由（对照硬性指标逐条打分）：**

1. **16 路 DO 单模块满足** ✅ —— ET-7042 恰好 16 路隔离开漏输出，不需要两台拼凑。
2. **输出形式与 N1616 一致** ✅ —— 隔离开漏 Sink（NPN，5~30V，100mA/ch），接线方式（DO.PWR / DOx / DO.GND）与现有 DB37 方案一致，**最小改动**。
3. **隔离完备** ✅ —— 3750VDC 场-逻辑隔离，与 N1616 光隔同级；PLC 侧另有 24V 光隔，双端隔离最稳。
4. **资料齐全** ✅ —— 官方产品页 + 数据手册公开可下载（本报告已附链接），Modbus TCP 寄存器表与接线图齐备。
5. **编程最简单、最可靠** ✅ —— PC 侧走以太网 Modbus TCP：**无需安装板卡驱动**（原 CC1616.dll 驱动问题彻底消除）、无 RS-485 布线/共地干扰问题；LW Vision 用 Qt 内置 `QModbusTcpClient` 即可，**不引入新依赖**；内置 Web 页可配置 IP 与输出上电值/安全值。
6. **采购容易** ✅ —— 泓格为台湾上市工控厂商，16DO 隔离模块为常备型号，代理体系完善。

**备选方案（视现场偏好）：**
- 若现场惯用 RS-485 串口远程 I/O（或工控机无空闲网口）：**ICP DAS I-8057**（同一 16DO 隔离开漏核心，Modbus RTU），成本略低、接线传统。这是"RTU 版首选"。
- 若希望顺便补回 N1616 的 16 路 DI（如后续需要相机触发/到位信号回读）：可在 I-8057 基础上加配 **I-8053**（16DI，隔离）或改用研华 **ADAM-4055×2**（2×8DO + 2×8DI，合计 16DO+16DI，但为两台模块 + 一个 RS-485 站址各配一台，成本更高、复杂度增加，不推荐作为首选）。
- 类别 B 板卡路线（PCI-1756 / USB-4751）仅在"不允许上位机与 PLC 走网络/串口、必须板卡直连"的场合才考虑，且需重写驱动层，**不推荐**。

## 五、附：完全不用硬件的替代路线评估（上位机 Modbus 直接写 PLC）

> 需求提示：PLC 梯形图当前用 X7~X36 硬接线驱动 M7/M10/M27 等结果位。评估"上位机直接写 M 位 / 写 D4600+ 结果数组"的可行性。

### 5.1 可行性结论：**技术上完全可行**，且是成本最低的方案

- **PLC 侧能力**：用户 PLC 为 **XD5-48T-E**——`-E` 后缀即**以太网机型（XD5E 系列）**。信捷 XD5E 本体自带 RJ45，官方支持 **MODBUS-TCP**、自由口、程序上下载/在线监控（见《XD/XL 系列用户手册【硬件篇】》"Ethernet 通讯"章节）。上位机可作为 Modbus TCP 客户端（端口 502，Unit ID=1）直接读写软元件。
- **软元件容量**：XD5 系列 M 区非掉电保持达 **70000 点**（M0~M69999，V3.4.6+ 固件），D 区 **D0~D69999**，**M7/M10/M27 与 D4600+ 均在范围内**，地址完全够用。
- **两种改写方式**：
  1. **写 M 线圈**（最小改动）：上位机用功能码 05/0F 直接写 M7/M10/M27 等结果位；梯形图把原来 "LD X7 → OUT M7" 的过渡删掉，直接用 M7 做后续判定。改动只涉及 1 条过渡梯级 + 删除 16 条硬接线。
  2. **写 D 结果数组**（更结构化）：上位机把 8 工位结果打包写 D4600 起（如每工位一个 D：0=NG/1=OK，或按位打包进 1~2 个字）；梯形图用 `MOV`/`CMP`/`BMOV` 读取并映射到 M 或直接参与判定。方便 HMI/上位机做数据记录与追溯。
- **LW Vision 软件侧**：Qt 内置 SerialBus 模块（`QModbusTcpClient` / `QModbusRtuSerialMaster`），**无需引入新第三方库**，与项目"不新增依赖"约束吻合。

### 5.2 必须注意的可靠性与安全性问题（这是本路线的关键成本）

1. **通信中断降级**：硬件 IO 断线时 PLC 输入自然为 0（=NG），属"失效安全"；而 Modbus 软写 M 在**上位机崩溃 / 网线断开时 M 位保持旧值**，可能把故障当 OK。**必须在梯形图中加"结果有效/心跳"机制**：上位机周期性（如每 50~100ms）递增写入一个心跳寄存器（如 D4690），梯形图用比较指令监视其变化，超过 N 个扫描周期未变化即把 8 工位结果**全部判为 NG 并报警**。
2. **实时性**：局域网 Modbus TCP 单次写往返约 1~5ms，对转盘筛选（通常每工位停留 ≥ 数十 ms）实时性足够；但不要依赖扫描周期边缘极窄的逻辑，建议 PLC 侧对结果做锁存（上升沿捕获）。
3. **程序改动与验收**：需在 XDPPro 中修改梯形图（删 X→M 过渡、加心跳看门狗、加通信初始化），并做完整空载/联调测试；相比"换一块 I/O 模块、PLC 程序不动"的硬件方案，改动风险更高。
4. **与硬件方案的关系**：Modbus 直写路线与"I-8057/ET-7042 硬件 IO"路线不冲突——若最终选硬件模块，**仍可保留 Modbus TCP 通道**，两路冗余，或作为日后免布线的演进方向。

### 5.3 两路线对比

| 维度 | 硬件 I/O（ET-7042 / I-8057） | Modbus 直写 M/D |
|---|---|---|
| 成本 | 约 1~2 千元 + 16 根信号线 | 仅软件（≈0 硬件成本） |
| PLC 程序改动 | 无（保持 X7~X26 硬接） | 需删过渡、加心跳看门狗、通信初始化 |
| 上位机改动 | 用 QModbus 客户端写 DO（简单） | 用 QModbus 客户端写 M/D（同样简单） |
| 可靠性 | 断线=NG，失效安全 | 需自行实现心跳/超时判 NG，否则有风险 |
| 数据追溯 | 仅有开关量 | 可顺带回传数值结果（D 数组），利于追溯 |
| 推荐场景 | **首选（改动小、可靠）** | 预算极紧 / 想免接线时的次选，或与硬件并行作冗余 |

> **总体建议**：首选 **ICP DAS ET-7042** 硬件方案（改动最小、双端隔离、失效安全）；Modbus 直写作为**低成本备选或冗余通道**，采用时务必落实"心跳看门狗判 NG"。
